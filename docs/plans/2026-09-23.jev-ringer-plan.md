# Jev in ringer Implementation Plan

> For executors: tasks use checkbox syntax; execute in dependency order; a task is done when its
> acceptance check passes. No specific tooling, harness, or skills are assumed.

**Goal:** Ringer records a Jev-assigned `task_type` when Jev is confident, and (after an offline replay gate) skips the automatic retry on FAILs Jev flags as check faults, proposing the exact `amend` command instead.
**Approach:** A stdlib `urllib` client inside `ringer.py`, behind a master switch plus one switch per feature, all default off, called off the asyncio event loop with a hard timeout and a per-invocation breaker that falls back to today's behavior.
The task_type decision runs in `lint` and at run time with an on-disk answer cache; the scoreboard gains per-bucket hand/Jev counts; an offline replay script over `~/.ringer/runs.jsonl` gates the FAIL flag, which lands last because it touches the retry loop.
**Tech stack:** Python 3.12+ stdlib only (`urllib.request`, `asyncio.to_thread`, `tomllib`, `sqlite3`, `http.server` for the test stub), single-file `ringer.py`, `unittest`.
**Source brief:** docs/briefs/2026-09-23.jev-ringer-brief.md

## Global constraints

- Stdlib only; no new dependency anywhere, including the replay script (`CONTRIBUTING.md:18`).
- `ringer.py` stays a single file; every task that edits it runs serially.
- All Jev switches default off: `enabled = false`, `task_type = false`, `fail_flag = false`.
- Off means byte-identical: with the master switch or a feature switch off, lint output, run output, and attempt-row keys match today exactly.
- The API key is read only from the `TYPESAFE_API_KEY` environment variable; never from config, never logged, never printed.
- Ringer never retries a Jev request.
- All Jev calls in one `run` share one `asyncio.Semaphore(JEV_MAX_CONCURRENT_CALLS)` with `JEV_MAX_CONCURRENT_CALLS = 4` (a constant, not config).
- Each feature has its own breaker; a tripped breaker prints exactly one stderr line, `jev: skipped <feature> (<reason>); continuing without Jev`, where `<feature>` is `task_type` or `fail_flag`.
- Declared field caps: task_type `task_spec` 12000 chars; FAIL flag `task_spec` 500 chars and `check_output` 2000 chars.
- Cutoffs: `task_type_cutoff = 0.9` and `fail_flag_cutoff = 0.9`; a confidence exactly equal to the cutoff meets it.
- Held-out list default: `["research", "probe", "persona-review"]`.
- Model default: `jev-1.13.0`; endpoint default: `https://api.typesafe.ai/v1/systemone`.
- The suite passes offline with `TYPESAFE_API_KEY` unset: `env -u TYPESAFE_API_KEY python3 -m unittest discover -s tests`.
- CLI tests set `RINGER_NO_SELF_UPDATE=1` (plus `RINGER_NO_CATALOG_REFRESH=1` and a temp `RINGER_HOME`).
- Jev never writes amendment rows; only the `amend` command does.
- Commit messages are plain, with no co-author trailer.
- Never hand-edit CHANGELOG files or any auto-generated file.
- Never use the em dash character in code, docs, or messages; use a plain "-".

## Decisions

Replay denominator: 47 (run_id, task_key) pairs have a FAIL in `~/.ringer/runs.jsonl`; 15 carry a hand label (check_bug 11, spec_defect 2, lane_outage 2) and 32 are un-amended; 20 pairs had a logged retry that passed.
The brief's bar is kept as written: at least 9 of the 11 check_bug pairs flagged.
The 2 other amended pairs have no FAIL (`T1-ruff-green` is TIMEOUT-only, one `T1-script` run is ERROR-only) and cannot be replayed.
These counts were re-derived in planning with an independent script over the log on 2026-09-23.

- D1 Config: `[jev]` TOML table -> frozen `JevConfig` as `AppConfig.jev` (default factory, all off); keys and defaults as in Global constraints plus `timeout_s = 5.0`; no env override; malformed values raise `ValueError` like `load_update_config` (ringer.py:1117) and `load_artifact_config` (ringer.py:1019); `config.sample.toml` gets a commented block; standalone `lint` reads only the `[jev]` table, tolerantly, so a missing or broken config file behaves as today.
- D2 Client: sync `jev_call(config, state, questions) -> JevResult` never raises; skip reasons `no-key`, `timeout`, `network`, `http-<status>`, `bad-response`, `error-<ExceptionType>`; async wrapper `asyncio.wait_for(asyncio.to_thread(jev_call, ...), timeout_s + 1)`, entered only after the Jev-only semaphore is acquired, so queue time never eats the timeout budget.
  One breaker `JevSession` per feature per invocation: it trips only on service-level reasons (`no-key`, `network`, `timeout`, `http-401`, `http-429`, any `http-5xx` including `http-529`), prints `jev: skipped <feature> (<reason>); continuing without Jev` once, and disables further calls for that feature only, so a task_type failure never disables the FAIL flag.
  Request-specific reasons (`http-422`, other 4xx, `bad-response`, `error-<ExceptionType>`) skip that one decision, are recorded on the row, and do not trip.
  Response `model` and `usage` are logged on every row that used Jev.
- D3 Batching: one HTTP request per decision (task_type for one task; FAIL flag for one FAIL) carrying all of that decision's questions; task_type stays one task per request with state `{"task_spec": ...}`.
- D4 task_type: runs in standalone `lint` and once per task at the top of `_run_task` (not in the lint pass `run` performs); cache `ringer_home()/jev-cache.jsonl` keyed by sha256 of `["task_type-v1", model, spec_sent]` storing Jev's raw answer; `redact_spec` tasks never sent; `decide_task_type` rule; lint info lines prefixed `jev: <key>: task_type=...` (never `lint:`, so they cannot read as findings) ending `-> overrides hand` (Jev's label used and different), `-> agrees` (used and equal), or `-> keeps hand (<reason>)`; row fields `task_type`, `task_type_source`, `task_type_hand`, `jev_task_type` only when the feature is active.
  `task_type_source` is `jev` whenever Jev's answer was used, including when it equals the hand label, because the brief counts who labeled a task, not who changed it.
- D5 Scoreboard: per-group `task_type_sources: {"hand": n, "jev": n}` from each task's final attempt row (`task_type_source`, else `hand` when task_type is non-empty, else neither); text header `Task type: docs (hand 40, jev 8)`, where `jev` counts tasks whose recorded label came from Jev whether or not it matched the hand label; counts are shown (text and JSON) only when the input holds at least one Jev-labeled task, so a Jev-free log prints exactly today's output; `ringer.db` column `task_type_source TEXT`, schema version 3 -> 4; Postgres drops it like `task_type`.
- D6 FAIL flag: only when verdict is `FAIL` and `attempt < max_attempts`, computed before `_log_attempt`; a `redact_spec` task sends nothing and its row records `jev_fail_flag = {"skipped": "redact_spec"}`; state from `jev_fail_state(logged_spec, check_output)`; contract `fail_flag-v1` with questions `fault` and `check_cause` (wording in Task 1); flagged iff `fault.choice == "check"` and `fault.confidence >= cutoff`; a flag skips the retry, keeps verdict `FAIL`, prints the cause and amend command, lists the task again in the end-of-run summary, and records `jev_fail_flag` on the FAIL row.
  The amend command always carries `--log <resolved eval jsonl_path>`, because `run_amend_command` (ringer.py:8787) otherwise resolves the log from the default config and would append to the wrong append-only log under a non-default `--config`.
- D7 Redaction: none beyond the declared fields, their caps, and honoring `redact_spec`, which neither decision point ever sends; `docs/JEV.md` says so plainly.
- D8 Declared fields: `JEV_DECLARED_FIELDS` constant equals the table in `docs/JEV.md` (a test parses it); stub-captured requests carry exactly those keys within caps.
- D9 Triage: `triage_run` carries `jev_fail_flag` for flagged rows only; the printer puts ` [jev: check fault <cause> <confidence>]` right after `[unresolved]`/`[amended]` and before the multi-line check excerpt, then prints `  jev: to record it, run: <amend command>` on its own line; unflagged rows print as today.
- D10 Replay: `scripts/jev_fail_replay.py` (`--log`, `--labels`, `--out`, `--config`, `--dry-run`), unit = first FAIL per pair, outputs `results.jsonl`, `summary.json`, `review.csv`, resumable; a redacted row is skipped exactly like the live flag; amend commands name the replayed `--log`; the live replay is a human checkpoint.
- D13 HC2 pass rule: `bad = hand-judged wrong + known_wrong_flags`, where `known_wrong_flags` counts flagged pairs whose logged retry passed (`false_flags`) or whose label is `lane_outage`, each pair once; the gate passes when `bad <= 0.2 * flags_total`.
  A `spec_defect` flag counts as wrong only when its retry passed, which `false_flags` already covers, because skipping the retry of an unsatisfiable spec saves the same worker time.
- D11 Tests: stub selected by `[jev] endpoint = "http://127.0.0.1:<port>/v1/systemone"`; helper `tests/jev_stub.py`; fixture `tests/fixtures/jev_task_type_responses.jsonl` from the pilot's recorded outputs with synthetic specs.
- D12 Concurrency: with `max_parallel = 2`, a hung task_type call for task A does not delay task B's attempt row, and A runs with its hand label after the timeout.

Planning decisions (not in the handoff; each is reversible):

- P1 The Jev task_type call happens at the top of `_run_task`, before `async with self.semaphore`, so a slow call never holds a worker slot.
- P2 When Jev's label is used, `runtime.task` is replaced with `dataclasses.replace(task, task_type=recorded)`, so the row, the `task_type=` notes line, the steering observation, and Ringside all show the recorded value.
- P3 `jev_task_type` on a row also carries `"cached": true|false` so cost accounting never double-counts a cache hit.
- P4 Lint prints no per-task line for a task skipped by a tripped breaker; the single stderr breaker line explains why, and stdout stays identical to today.
  A request-specific skip does print `jev: <key>: task_type skipped (<reason>) hand=<hand> -> keeps hand`, because nothing else would tell the operator that one task's request failed.
- P5 The fixture's synthetic specs are `"fixture spec <task_key>: synthetic stand-in text for a pilot task, long enough to pass the underspecified-spec lint rule."`, because the handoff's 30-char form trips the `< 80` chars lint rule (ringer.py:1832) and `lint: clean` would never print.
- P6 In-process client tests set the dummy key with `mock.patch.dict(os.environ, ...)`, which restores the environment on exit; CLI tests set it in the subprocess env only.
- P7 The replay stops at the first skipped call with exit 1 and writes no row for it; a rerun resumes.
  It also rejects a labels file that names a pair with no FAIL, or omits an amended FAIL pair.
- P8 `models` text headers sum `task_type_sources` over the groups printed under that header (headers can repeat for the unattributed block, ringer.py:8523-8531).
- P9 The shared helpers `jev_fail_flag_record` and `jev_check_output_from_notes` live in Task 1 so the replay and the runtime build identical records.
- P10 The schema bump is purely additive: rows ingested before the bump read `task_type_source` as NULL and count as `hand`; `./ringer.py db rebuild` re-ingests if a long-running older HUD ingested Jev rows before the migration.
- P11 The scoreboard's hand/Jev counts are shown only when the input holds at least one Jev-labeled task, because `models` only reads the log and has no switch to consult; this keeps a Jev-free log byte-identical to today (brief, "In every case") while never hiding the source of a Jev label once one exists.

Review: a two-lens Rubix review ran on 2026-09-23; 9 findings were accepted (R1 `--log` in the amend command, R2 no FAIL flag for `redact_spec`, R3 Jev-only semaphore plus per-feature service-level breakers, R4 lane_outage flags count as wrong, R5 `jev:` prefix on lint info lines, R6 `overrides hand`/`agrees` wording, R7 flagged tasks in the run summary and triage tag placement, R8 ordering-only timing tests, R11 `error-<ExceptionType>`) and 5 were declined:
- A file lock on `jev-cache.jsonl`: declined, because appends are single short lines and a duplicate entry is harmless (last one wins).
- Deduplicating identical specs across tasks: declined, because about 100 calls a month costs under a cent and the cache already dedupes across invocations.
- Dropping the untyped nudge from `run`'s lint pass: declined, because it is existing behavior outside this brief.
- Parallel Jev calls in `lint`: declined, because lint is interactive, small, and cache-backed, and sequential calls keep its output order trivially stable.
- A daemon-thread pool for slow-drip servers: declined, because `run` is already bounded by `wait_for` and the residual lint risk is named under Risks.

Facts that differ from the planning handoff (verified in `ringer.py` at commit 51bfc9b):

- An env var does override a TOML key today: `RINGER_STEERING_DIR` overrides `[steering] dir` (ringer.py:835); the no-override decision for `[jev]` stands.
- `load_steering_config` swallows errors while `load_update_config` and `load_artifact_config` raise `ValueError`; `[jev]` follows the raising pair.
- Three existing tests assert schema version 3 (tests/test_model_db.py:183-184, tests/test_taxonomy.py:299-300, tests/test_identity_evidence.py:191-192); Task 3 updates them to 4.
- `tests/test_ringer.py` `run_ringer` sets only `RINGER_NO_SELF_UPDATE` (not `RINGER_HOME` or `RINGER_NO_CATALOG_REFRESH`); the new Jev CLI helper sets all three.
- Current line numbers: lint dispatch ringer.py:11282-11292, `AppConfig.load(args.config)` ringer.py:11297, run's lint pass ringer.py:11325-11332, `_log_attempt` call ringer.py:9026, retry decision ringer.py:9035.

## Human checkpoints

- HC1 (after Task 4, owner-fired, sends 47 real specs and check outputs to TypeSafe): run the live replay with the exact command in How to run, then the executed bar check on `summary.json` (`bar_met` must be `true`, criterion 9).
  Estimated cost: 47 calls at about 1,500 input tokens each is about 70,500 tokens, about $0.003 (estimate, not measured).
- HC2 (after HC1, `[judgment]`, criterion 10): fill the `verdict` column of `review.csv` with `right` or `wrong` for every row, then run the score command in How to run.
  Pass rule (D13): hand-judged `wrong` rows plus `known_wrong_flags` from `summary.json` total at most 20% of `flags_total`.
  `known_wrong_flags` counts each flagged pair once when its logged retry passed (`false_flags`) or its label is `lane_outage`; a `spec_defect` flag is wrong only when its retry passed.
  If HC1 or HC2 misses, one rewording is allowed: edit only the `instructions` and criteria descriptions inside `JEV_FAIL_QUESTIONS` in `ringer.py` (option keys unchanged), set `JEV_CONTRACT_FAIL_FLAG = "fail_flag-v2"`, update the contract-id assertion in `tests/test_jev_plumbing.py`, run the full suite, commit with `git commit -m "jev: reword FAIL-flag questions as fail_flag-v2"`, and replay into the `v2` out dir.
  If v2 still misses either rule, Task 5 is not executed, the FAIL flag is parked, and the task_type work ships alone.
- HC3a (after Task 3, owner-fired, sends 3 pilot specs): live task_type smoke with the owner's key; lint shows labels, run records rows, `models` shows hand/Jev counts; Jev's choices should match the pilot's `responses.jsonl` (the pilot used the `jev-latest` alias, so confidences may differ slightly).
- HC3b (after Task 5, owner-fired, sends one synthetic spec): live FAIL-flag smoke; afterwards the owner alone sets `fail_flag = true` in their own `~/.config/ringer/config.toml`.

def fail_flag_response(fault: str, confidence: float, cause: str, cause_confidence: float = 0.9) -> dict[str, Any]:
    """A /v1/systemone response body answering the fail_flag-v1 questions."""

    def spread(options: tuple[str, ...], chosen: str, top: float) -> dict[str, float]:
        rest = round((1 - top) / (len(options) - 1), 4)
        return {option: (top if option == chosen else rest) for option in options}

    return {
        "model": "jev-1.13.0",
        "answers": {
            "fault": {"type": "choice", "choice": fault, "confidence": confidence,
                      "probabilities": spread(FAULT_OPTIONS, fault, confidence)},
            "check_cause": {"type": "choice", "choice": cause, "confidence": cause_confidence,
                            "probabilities": spread(CAUSE_OPTIONS, cause, cause_confidence)},
        },
        "usage": {"input_tokens": 900, "output_tokens": 60},
    }

        self.hang_questions: set[str] = set()  # hang requests that ask any of these question ids

        self._lock = threading.Lock()
        self._server: ThreadingHTTPServer | None = None

    @property
    def count(self) -> int:
        with self._lock:
            return len(self.requests)

    def bodies(self) -> list[dict[str, Any]]:
        with self._lock:
            return [item["body"] for item in self.requests]

    def start(self) -> str:
        stub = self

        class Handler(BaseHTTPRequestHandler):
            def log_message(self, format: str, *args: Any) -> None:
                return

            def do_POST(self) -> None:
                length = int(self.headers.get("Content-Length") or 0)
                raw = self.rfile.read(length)
                try:
                    body = json.loads(raw.decode("utf-8"))
                except (UnicodeDecodeError, json.JSONDecodeError):
                    body = {"unparseable": raw.decode("utf-8", errors="replace")}
                record = {
                    "body": body,
                    "path": self.path,
                    "authorization": self.headers.get("Authorization"),
                    "content_type": self.headers.get("Content-Type"),
                    "arrived": time.time(),
                    "released": None,
                }
                with stub._lock:
                    stub.requests.append(record)
                state = body.get("state") if isinstance(body, dict) else None
                task_spec = state.get("task_spec") if isinstance(state, dict) else None
                questions = body.get("questions") if isinstance(body, dict) else None
                asked = set(questions) if isinstance(questions, dict) else set()
                if task_spec in stub.hang_specs or stub.hang_questions & asked:
                    time.sleep(stub.hang_s)
                record["released"] = time.time()
                if stub.status != 200:
                    self._send(stub.status, json.dumps({"error": f"stub status {stub.status}"}).encode("utf-8"))
                    return
                if stub.malformed:
                    self._send(200, b"{not json")
                    return
                response = stub.responses.get(task_spec) if isinstance(task_spec, str) else None
                if response is None:
                    self._send(422, json.dumps({"error": "stub has no response for this task_spec"}).encode("utf-8"))
                    return
                self._send(200, json.dumps(response).encode("utf-8"))

            def _send(self, status: int, payload: bytes) -> None:
                try:
                    self.send_response(status)
                    self.send_header("Content-Type", "application/json")
                    self.send_header("Content-Length", str(len(payload)))
                    self.end_headers()
                    self.wfile.write(payload)
                except (BrokenPipeError, ConnectionResetError):
                    pass

        server = ThreadingHTTPServer(("127.0.0.1", 0), Handler)
        server.daemon_threads = True
        server.block_on_close = False
        self._server = server
        threading.Thread(target=server.serve_forever, daemon=True).start()
        return f"http://127.0.0.1:{server.server_address[1]}/v1/systemone"

    def stop(self) -> None:
        if self._server is not None:
            self._server.shutdown()
            self._server.server_close()
            self._server = None

def jev_call(config: JevConfig, state: dict[str, str], questions: dict[str, dict[str, Any]]) -> JevResult:
    """One Jev request. Never raises: any failure is a JevResult with a skip reason."""
    key = os.environ.get(JEV_API_KEY_ENV, "").strip()
    if not key:
        return JevResult(skipped="no-key")
    try:
        body = json.dumps({"state": state, "model": config.model, "questions": questions}).encode("utf-8")
        request = urllib.request.Request(
            config.endpoint,
            data=body,
            method="POST",
            headers={
                "Authorization": f"Bearer {key}",
                "Content-Type": "application/json",
                "User-Agent": "ringer.py",
            },
        )
        with urllib.request.urlopen(request, timeout=config.timeout_s) as response:
            raw = response.read()
    except urllib.error.HTTPError as exc:
        return JevResult(skipped=f"http-{exc.code}")
    except TimeoutError:
        return JevResult(skipped="timeout")
    except urllib.error.URLError as exc:
        return JevResult(skipped="timeout" if isinstance(exc.reason, TimeoutError) else "network")
    except (OSError, http.client.HTTPException):
        return JevResult(skipped="network")
    except Exception as exc:
        return JevResult(skipped=f"error-{type(exc).__name__}")
    return parse_jev_response(raw, questions)

            print(f"jev: skipped {self.feature} ({result.skipped}); continuing without Jev", file=sys.stderr)
        return result

    def call(self, state: dict[str, str], questions: dict[str, dict[str, Any]]) -> JevResult:
        if self.skip_reason:
            return JevResult(skipped=self.skip_reason)
        return self._note(jev_call(self.config, state, questions))

    async def call_async(self, state: dict[str, str], questions: dict[str, dict[str, Any]]) -> JevResult:
        if self.limiter is None:
            return await self._call_async(state, questions)
        async with self.limiter:  # queue time is spent here, before the wait_for budget starts
            return await self._call_async(state, questions)

    async def _call_async(self, state: dict[str, str], questions: dict[str, dict[str, Any]]) -> JevResult:
        if self.skip_reason:  # checked after the limiter, so queued calls see a breaker that tripped meanwhile
            return JevResult(skipped=self.skip_reason)
        return self._note(await jev_call_async(self.config, state, questions))

# Jev in ringer

Ringer can ask Jev, the System One model from TypeSafe, for help with two decisions it makes badly on its own.
Every Jev feature is off by default.
With the master switch off, the API key unset, or the API unreachable, ringer behaves exactly as it does without Jev.

## Switches

All settings live in the `[jev]` table of `config.toml`, and no environment variable overrides them.
A feature runs only when `enabled` and that feature's own switch are both `true`.
Each feature has its own section below; a switch whose section is missing has no effect yet.

| Key                | Default                                   | Meaning                                                              |
|--------------------|-------------------------------------------|----------------------------------------------------------------------|
| `enabled`          | `false`                                   | Master switch; no Jev feature runs unless this is `true`.            |
| `task_type`        | `false`                                   | Record the task_type Jev assigns, in `lint` and `run`.               |
| `fail_flag`        | `false`                                   | Ask Jev whether a FAIL is the check's fault before the retry.        |
| `model`            | `"jev-1.13.0"`                            | Pinned model version sent with every request.                        |
| `endpoint`         | `"https://api.typesafe.ai/v1/systemone"`  | TypeSafe System One endpoint.                                        |
| `timeout_s`        | `5.0`                                     | Hard timeout for one request, in seconds.                            |
| `task_type_cutoff` | `0.9`                                     | Lowest Jev confidence at which its task_type is recorded.            |
| `fail_flag_cutoff` | `0.9`                                     | Lowest Jev confidence at which a FAIL is flagged as a check fault.   |
| `held_out`         | `["research", "probe", "persona-review"]` | Task types Jev never assigns or overrides; edit the list to release. |

## API key

The key is read from the `TYPESAFE_API_KEY` environment variable only.
It is never read from config, never logged, and never printed.
Without it, Jev is skipped with one line on stderr, and ringer carries on as it does today.

## Declared fields

Each decision point sends exactly one request, and that request carries only these state fields, cut to these caps.
The text leaves this host verbatim up to the cap; ringer applies no other redaction.
A task with `"redact_spec": true` sends nothing at all: task_type keeps the hand label, and a FAIL is retried as before with `{"skipped": "redact_spec"}` on its row.
The constant `JEV_DECLARED_FIELDS` in `ringer.py` must equal this table, and `tests/test_jev_plumbing.py` fails if they drift.

| Decision point | Field          | Source                                                | Cap (chars) |
|----------------|----------------|-------------------------------------------------------|-------------|
| `task_type`    | `task_spec`    | The manifest task's `spec`                            | 12000       |
| `fail_flag`    | `task_spec`    | The FAIL row's logged `spec` (`spec[:500]`)           | 500         |
| `fail_flag`    | `check_output` | The check output excerpt the FAIL row logs in `notes` | 2000        |

## Fallback

Every request runs off the asyncio event loop with a hard timeout, so a slow or hanging API never stalls other tasks.
During `run`, at most 4 Jev requests are in flight at once, and time spent waiting for a slot does not count against `timeout_s`.
Ringer never retries a Jev request.
Each feature has its own breaker, so a task_type failure never turns off the FAIL flag.
A service-level failure prints one line on stderr and turns that feature off for the rest of the `lint` or `run` invocation:

```text
jev: skipped <feature> (<reason>); continuing without Jev
```

A request-specific failure skips only that one decision; it is recorded on the attempt row (and printed by `lint` for that task), and Jev stays on.

| Reason                  | Meaning                                                    | Turns the feature off |
|-------------------------|------------------------------------------------------------|-----------------------|
| `no-key`                | `TYPESAFE_API_KEY` is unset or empty; no request was sent. | yes                   |
| `timeout`               | No response within `timeout_s`.                            | yes                   |
| `network`               | Connection refused, DNS failure, or another network error. | yes                   |
| `http-401`              | Missing or invalid API key.                                | yes                   |
| `http-429`              | Rate limited.                                              | yes                   |
| `http-5xx`              | A server error, including `http-529` (overloaded).         | yes                   |
| `http-422`              | TypeSafe rejected this request body.                       | no                    |
| `http-<other 4xx>`      | Any other client error for this request.                   | no                    |
| `bad-response`          | The response was not the expected JSON shape.              | no                    |
| `error-<ExceptionType>` | An unexpected client-side error; ringer never raises.      | no                    |

```python
def decide_task_type(
    hand: str, answer: dict[str, Any] | None, cutoff: float, held_out: tuple[str, ...]
) -> tuple[str, str, str]:
    """Return (recorded task_type, source "hand"|"jev", reason the hand label was kept or "")."""
    if answer is None:
        return hand, "hand", "no-answer"
    choice = str(answer.get("choice") or "")
    if hand in held_out or choice in held_out:
        return hand, "hand", "held-out"
    if hand and hand not in JEV_TASK_TYPE_VOCAB:
        return hand, "hand", "hand-outside-vocabulary"
    if float(answer.get("confidence") or 0.0) < cutoff:
        return hand, "hand", "below-cutoff"
    return choice, "jev", ""
```

## Risks

- Loopback listeners: `tests/TESTING.md` notes that restricted sandboxes can reject local listeners; every stub-based test needs `127.0.0.1` binds (the existing Ringside tests already bind loopback ports and passed at baseline).
- Timing tests (D12 and the FAIL-flag hang test) use `timeout_s = 4.0` against an 8-second stub hang and assert ordering only; on a pathologically slow CI host the fix is to raise both together, never to drop the assertion.
- The HTTP question body is believed equivalent to the pilot's SDK `Choice` serialization but was not diffed against the SDK; HC3a compares live answers with the pilot's recorded ones to catch a mismatch.
- `urllib`'s timeout bounds each socket operation, not the whole request, so a server trickling bytes could exceed `timeout_s` in `lint`; the run loop is still bounded by `wait_for(timeout_s + 1)`.
